# QC — candidates, the witness judge, take, join and film QC

The Pipeline V2 QC modules: `agents/director/rubrics.js`, `agents/director/candidates.js`, `agents/director/qc.js`, the rubric books under `rules/rubrics/` and the `/api/film/image-stats` route. The interface is the one in [PIPELINE.md](PIPELINE.md) under "Implementation contracts"; this document explains the shapes and the decisions behind them.

## Rubric books

Four books, `rules/rubrics/{plate,take,join,film}.json`, each `{ version, set, params, questions }`. `loadRubrics(rulebook, books = readRubricBooks())` validates every question and refuses the whole load on the first defect — an unknown `ruleRef`, a `choice` without options, a `passes` list that every answer satisfies, an anchor declared but absent from the text, a placeholder in the text that is not a declared anchor, `evidenceRequired` anything but `true`, a params value missing or non-numeric.

A question:

| field | meaning |
|---|---|
| `id` | `<set>.<kebab-name>`, unique across the four books |
| `ruleRef` | the rule the question serves; must exist in `rules/cinematic.json` or `rules/screenwriting.json` |
| `form` / `options` | `binary` (yes / no) or `choice` with two or more options |
| `passes` | the answers that mean the rule is served |
| `scope` | the rubric family: `artifact`, `identity`, `setup`, `force`, `change`, `look`, `motion`, `exposure`, `action`, `continuity`, `direction`, `beat`, `story`. Authority is not keyed by scope: `policy.judge.spendingRubrics` lists rubric **ids** (the default policy lists the four artifact questions), and every id it does not list is witness. The report's `judge-authority-earned` guarantee accepts an artifact-scope id from day one and every other id only with a journaled `promotion` |
| `evidence` | `frame` (askable of a single still) or `sequence` (needs several frames). Candidate scoring asks only the `frame` questions of the take book |
| `evidenceRequired` | always `true`: every answer names the frame index that shows it |
| `anchors` | the placeholders the harness fills from the shot, the plate or the style: `subject`, `force`, `change`, `setup`, `look`, `entity`, `role`, `beat`, `firstBeat`, `lastBeat` |
| `measure` | a measurement twin (`frozen`, `black`, `cut`, `continuous`): a stable answer that contradicts the measurement is a judge-reliability row, never a film finding |
| `joinTypes` | join book only: which declared join types the question is asked of |
| `level` | film book only: `shot` questions ride segment-wise, `film` questions ride once over the whole film |

Judgment rules that no question cites are returned as `doctrineOnly` (today: CIN-011, SCR-009, SCR-010) — they stay prompt doctrine.

`params` carries every threshold the deterministic checks use, with provenance: the judge frame width, the still checks (luminance range, blur floor, near-duplicate bits), the frozen-segment definition (max dHash delta, minimum seconds), black and blown luminance, the scoring weights, the join window. A missing value is a load error; nothing defaults.

Rule-reference gaps, stated rather than hidden: the cinematic book has no artifact rule and no look rule. Artifact questions (anatomy, morphing, garbled writing, plate integrity) cite CIN-009 as the nearest take-integrity rule; look questions cite SCR-008, the brief that carries the look. When the cinematic book's owner lands dedicated rules, the `ruleRef`s move by a one-line edit per question.

## The judge protocol

`judge()` in `qc.js` is the only path to `client.reason` with images. Every call is journaled as a `judge` step with the full prompts, the frames with their times, the reference plates, the order, the raw answer and the parsed answers.

Every `judge()` call names the plan node that spends it: `nodeId` is required and a call without one throws `E-JUDGE-NO-NODE` before any model call. The callers supply `keyframe:<shot>` (candidate scoring), `qc:<shot>` (take QC), `chain:<shot>` (join QC), `plate:<entity>` (plate QC) and `final` (film QC). The id rides on every `client.reason` call the judge makes, both question orders and the falsification re-ask, so the pass's reserving client reserves the judge call under that node rather than the stage it happened during; the id is stripped before the wire.

What one `judge()` can spend is declared as `JUDGE_PROTOCOL` in `agents/director/policy.js`: two orders at the primary offset (`callsPerItem.base`, 2) and at most both orders at both offsets plus the falsification (`callsPerItem.max`, 5). The approval arithmetic multiplies every judged item by it, the qc suite pins the two counts to the protocol, and each of the calls is reserved under the node the judge names.

1. Both question orders — listed and reversed — on the same frames. A question is `stable` only when both orders agree; otherwise `unstable`, or `malformed` when an answer is missing, off-list or points at no frame.
2. A second frame offset (half a sample period later) on any stable failure, again in both orders. A failure holds only when it repeats; a pass overturns it; disagreement makes it unstable.
3. A falsification re-ask for every held failure: the judge points at the single frame that shows it. A judge that answers the re-ask and cannot point withdraws the failure (`unfalsified`). A re-ask the harness cannot parse — no JSON, or no `falsifications` array — is a parse fault, not a judgment: every held failure keeps its `stable` failing verdict (it was confirmed by both orders and, when it failed at the primary offset, by the second), its `falsification` records `{ pointed: false, malformed }`, and one `judge-reliability` note `E-JUDGE-MALFORMED` carries the raw response and the held question ids. Only a parsed reply with `seen: false` produces `unfalsified`.
4. Contradiction against measurement for questions with a `measure` twin: the measurement stands, the verdict is `overruled`, and a `judge-reliability` row with code `E-JUDGE-CONTRADICTS-MEASURE` is filed.
5. A blind control on a policy-declared fraction of shots. Every `judge()` call separates what it tells the judge into `context` — the harness facts: what the frames are, how they were sampled, what was measured, where a boundary sits — and `description` — the plan's prose: subject, force, change, setup, look, planned seconds, declared join type, the plate's prompt. Both are required (`E-JUDGE-NO-CONTEXT`, `E-JUDGE-NO-DESCRIPTION`). Every call also names `blind: { key, fraction }` (`E-JUDGE-BLIND-KEY`, `E-JUDGE-BLIND-FRACTION` before any model call); the callers build it with `blindOf(policy, key)` from `policy.judge.blindFraction`, and the key is the shot id for candidate scoring, take QC, join QC (the join's next shot) and a film segment (its first shot), the entity for plate QC and `film` for the whole-film questions. Selection is deterministic: the FNV-1a hash of the key over 2^32 is the draw, and the shot is a blind control when the draw is under the fraction — so one shot is blind in every judgment made of it, on every resume and replay, and a different policy fraction moves the boundary, never the order. On a blind shot the description is withheld from every ask (both orders, the second offset, the falsification) and the judge answers the rubric from the frames, the references and the questions alone; the call count does not change. Every `judge` step records `blind: { key, fraction, hash, draw, selected }` and the `description` it showed (`null` when withheld); the callers record `blind` on their `qc` and `score` steps and inside every finding's evidence. The control is read across shots by lane D: the judge's agreement with the creator's notes on blind shots against described shots says whether the description leads the judge, which is why the constitution declares the fraction over shots and not over calls.

Unstable, malformed and unfalsified verdicts each file a `judge-reliability` note (`E-JUDGE-UNSTABLE`, `E-JUDGE-MALFORMED`, `E-JUDGE-UNFALSIFIED`). A held failure files a `qc` finding with code `E-RUBRIC-FAIL`: severity `blocker` and disposition `regenerate` when the question's id is in `policy.judge.spendingRubrics`, severity `note` and disposition `witness` otherwise — join and film questions included, so a creator who lists a join rubric has made it spend.

Reference plates ride as images before the frames, labelled R1..Rn; frame indices count frames only. A shot whose `force` is the SCR-013 `params.noForce` literal (`noForceLiteral(rubrics)`, refused by name when the rule carries none) skips every question anchored on force; the skipped ids and the reason ride on the `qc` and `score` steps.

## Candidates

`generateCandidates` renders K keyframes on the default image slot (`defaultImageModelKey()` → `getModel`, size from `keyframeImageSize`) with the plates as reference images, calling `reserve({ nodeId: 'keyframe:<shot>', kind: 'still', units: 1, justification })` before every still. Each still is saved through `journal.media` and journaled as a `candidate` step. A refused reservation propagates with `err.candidates` holding what was made.

`scoreCandidate({ candidate, siblings, policy, ... })` — `siblings` is the shot's whole candidate pool, earlier attempts included, so a regenerated candidate that duplicates one already made is caught; the keyframe node passes the pool. `policy` supplies the judge's blind fraction and the spending rubric ids. Deterministic components: dimensions equal the requested size, luminance within `params.still`, blur above the floor, no sibling within `duplicateMaxBits`, and plate similarity `1 − min dHash distance / 64`. Rubric component: passed / asked over the take book's `frame` questions. `score = deterministicWeight × deterministic + rubricWeight × rubric`.

`selectCandidate` ranks by score (ties by id), journals a `select` step with every score and the reason, and when the winner is under `policy.candidates.selectionFloor` files a `shortfall` finding (`E-SELECT-FLOOR`) and returns it — regeneration within budget is the scheduler's call. The keyframe node answers a shortfall with a `new-candidate` regeneration (cause: the shortfall's code) while its attempts are under `policy.attempts.candidate`; the pool survives the reset, so the next attempt selects over every candidate made so far. On the last attempt it journals a `completionDecision` (`promote-best`, cause `exhausted-candidate`, every candidate's score), files `E-KEYFRAME-FLOOR` naming the promoted candidate, and promotes the best it has.

## Take QC

Deterministic: `/api/film/measure` (duration, fps, first and last dHash), frames at `policy.judge.fps` through `/api/film/frames` (chunked by the route's 30-frame cap), `/api/film/image-stats` per frame. Frozen segments are runs of consecutive-frame dHash deltas at or under `params.frozen.maxBits` lasting at least `params.frozen.minSeconds`; black and blown frames come from mean luminance. The per-shot measure rules (CIN-004, CIN-007, CIN-009) run through their `CHECKS`; CIN-009's fractions are compared against its params here because the rule is calibrating (`null` records, a number blocks). The keyframe's dHash distance to the take's first frame is recorded. A take longer than `policy.judge.maxFramesPerCall` frames at the policy fps is refused by name — the policy is inconsistent, and a silent subsample would hide it.

Findings: `E-TAKE-FPS`, `E-TAKE-DURATION`, `E-TAKE-FROZEN`, `E-TAKE-BLACK`, `E-TAKE-BLOWN`, `E-RUBRIC-FAIL`, plus the judge-reliability rows. A measure gate whose rule is `deterministic` (CIN-004, the frame rate) is a model property no re-roll answers: it files as family `shortfall`, still a blocker, with disposition `ship`; a `retryable` gate (CIN-007) files as family `gate` with disposition `regenerate`. `pass` is the absence of blockers; `regenerate` is whether any finding asks for one, and the qc node reads the findings the same way: a take that fails on `ship` findings alone is shipped with a journaled `completionDecision { decision: 'ship-measured-blocker', cause: 'deterministic-measure-blocker', ruleIds, codes }` instead of being re-shot. `score` folds the deterministic components and the rubric fraction with the same weights as candidates.

## Join and film QC

`joinQC` measures both takes, samples `params.window` seconds either side of the boundary at the window fps, and hands the judge the boundary index in the `context` — dHash decided whether a cut exists; the judge is never asked to find one — while the declared join type rides in the `description` the blind control may withhold. Questions are filtered by the declared join type. The `cut` and `continuous` twins compare against CIN-012 `thetaChange` and CIN-003 `theta`; while those are `null` no contradiction is possible. joinQC's `policy` serves the blind fraction and the spending ids; under the default policy every join finding is a witness note. Every join finding carries `stage: 'join'`, the `joinRef` and the next shot's id; `takeId` is present only when the next side names a take, because the finding schema refuses a null id and a held still has none.

`filmQC` lays the manifest's shots on the measured timeline, samples the whole film at the policy fps, and asks the `shot`-level questions segment-wise, packing consecutive shots into one call only while the frame count stays at or under `policy.judge.maxFramesPerCall`. The `film`-level questions ride once, over the first and last sampled frame of every shot, evenly subsampled to the cap; the cast questions are asked once per subject named by the shots. `filmQC` takes `style` in addition to the contract's arguments (the look anchor needs it) and expects `screenplay.beats` (`[{ id, text }]`, the sequence's beat list) so each shot's beat can be named.

`plateQC({ plate, style, rubrics, policy, client, journal })` runs the plate book over a single plate for stage 5 and returns `{ pass, score, findings, stats, verdicts }`; `pass` is the absence of blockers, so under the default policy only the `artifact` question can fail a plate. The executor's plate node calls it after every plate render (see `docs/PIPELINE.md`, the nodes contract) and re-renders within `policy.attempts.plate`.

## Findings

Rows are built by `findingRow()` with `finding_id` and `at`; `family`, `stage`, `severity`, `code`, `detail`, `evidence`, `disposition` and the ids that apply are set by the caller. `evidence` is always an array of pointer objects (frames, verdicts, measurements, the blind record), as `FINDING_SCHEMA` requires. `runId` is stamped at the pass level by `passJournal` in `cli/bravo.js` — the pass knows its run; the QC modules do not.

## `/api/film/image-stats`

`POST { url }` → `{ width, height, meanLuma, blur, dhash }`. Accepts a store url, a `data:` url (what the frames route returns when check-in fails) or http(s). Width and height from ffprobe; mean luminance and blur (variance of the 3×3 Laplacian) from a 64×64 gray decode; dHash from the same 9×8 gray decode `measure.js` uses, so frame, plate and take hashes are comparable. Every request works inside its own `mkdtemp` scratch directory under the OS temp dir (`bravo-image-stats-*`): the source and both gray decodes are written there and the directory is removed in `finally`, so the concurrent requests `scoreCandidate` fans out under `concurrency.judge` never share a scratch file; `grayFrame` and `materialize` refuse by name without a directory.
